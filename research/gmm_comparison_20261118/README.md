# PSF 2·4·6·8 GMM 비교 실험

기존 설문과 저장 모델을 변경하지 않고, 입력을 묶는 방식이 CatBoost의 예측에 미치는 영향을 비교한다. 실행일: 2026-11-18.

## 비교 조건

| 코드 | 입력 | 확인할 질문 |
|---|---|---|
| `gmm` | 기존 묶음과 GMM 설정으로 만든 범주 | 현재 압축 방식의 기준 성능 |
| `raw_numeric` | 기존 엑셀로 숫자 매핑한 sub PSF 전체 | GMM 압축을 제거하면 나아지는가? |
| `raw_text` | 원본 응답 조건의 범주 문자열 전체 | 숫자 매핑에서 합쳐진 수준도 보존하면 나아지는가? |
| `raw_text_plus_gmm` | 원본 범주 전체 + GMM 최종 특성 전체 | 원정보를 보존하면서 GMM 특성을 추가하면 나아지는가? |

네 방식 모두 입력을 **범주형**으로 CatBoost에 전달한다. `raw_numeric`의 숫자는 연속형 수치로 처리하지 않는다. 결합 방식에는 GMM 묶음의 단일 변수 직접 매핑 특성도 포함한다. PSF2·4·8은 원변수 7개와 최종 특성 5개, PSF6은 원변수 14개와 최종 특성 6개다.

## 공통 검증 조건

- 원본 TXT에서 기존 노트북의 신원 정정, 설문 구분, `quality_95 == 성실` 필터를 재현한다. 이 필터 자체의 적절성은 이번 실험에서 바꾸거나 검증하지 않는다.
- 원본 범주 조합이 같은 응답을 하나의 시나리오 그룹으로 둔다. `GroupKFold(n_splits=5, shuffle=False)`로 나누고 네 방식에 같은 분할을 적용한다.
- 각 응답은 자신이 학습에 포함되지 않은 모델로 한 번 예측한다. 이것이 OOF(out-of-fold) 결과다.
- GMM은 각 fold의 학습 자료에서만 추정한다. 시험 자료를 GMM 학습에도 넣지 않는다. 같은 시나리오의 중복 응답은 함께 학습 또는 시험으로 이동한다.
- CatBoost는 기존 설정 그대로 사용한다: 500회, depth 6, learning rate 0.05, l2 20, Lossguide, max leaves 32, min data in leaf 2, random strength 10, bagging temperature 2, MultiClass, seed 42.
- 클래스 가중치, 리샘플링, 임계값 조정, 하이퍼파라미터 탐색을 적용하지 않는다. 출력 등급은 확률 최댓값으로 결정한다.
- 학습 구간의 응답 비율만 사용하는 기준 모델을 별도로 계산한다. 입력 특성 없이도 얻는 정확도와 확률 손실을 확인하기 위한 것이다.
- 저장 GMM과 전체 학습 자료로 기존 CatBoost를 재학습해 저장 모델의 확률과 일치하는지 확인한다. 이 확인의 전체 학습 자료 점수는 교차검증 성능으로 사용하지 않는다.

## 결과 읽는 법

- 정확도: 전체 응답에서 정답인 비율. 다수 등급만 출력해도 높게 나올 수 있다.
- 균형 정확도: 각 등급의 재현율을 동일하게 평균한 값. 환경에서 전부 `나쁨`이면 50%, 세 등급 문제에서 한 등급만 출력하면 약 33.33%다.
- 재현율: 실제 해당 등급인 응답 중 모델이 그 등급을 맞힌 비율. 환경의 `보통`을 찾는 능력을 직접 확인할 수 있다.
- Macro F1: 등급마다 정밀도와 재현율을 종합한 뒤 등급을 동일하게 평균한 값.
- Log loss: 실제 응답 등급에 부여한 확률의 손실. 낮을수록 좋다. 이 값이 좋아졌다고 확률 보정이 검증된 것은 아니다.
- 응답 비율: 각 설문 응답을 한 건으로 센 예측 비율. 가능한 전체 시나리오의 비율과 다르다. 고유한 관측 시나리오별 예측 건수는 `class_metrics.csv`에 따로 기록한다.

## 실행

Python과 `Railway_hep/requirements.txt`의 의존성을 준비하고, `Railway_hep/`에 원본 설문 TXT와 `CatBoost_Result/preprocess_v1.4.ipynb`, `CatBoost_Result/analysis_v1.5.ipynb`를 별도로 배치한다. 원본 설문 및 로컬 분석 노트북은 Git에 포함하지 않는다. 저장된 결과 검증도 원본 해시를 확인하므로 해당 자료가 필요하다.

저장소 루트에서 PowerShell로 실행한다.

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:LOKY_MAX_CPU_COUNT='2'
python -B research/gmm_comparison_20261118/run_comparison.py
```

완료된 PSF 결과를 재사용하려면 `--resume`을 추가한다. 입력 파일, 실행 코드, 설정, 라이브러리 버전으로 만든 서명이 같을 때만 재사용한다. 다른 결과 폴더는 `--output`으로 지정한다. 원본 `Railway_hep` 안을 출력 위치로 지정하면 실행을 중단한다.

전처리 노트북은 SHA-256으로 고정되어 있다. 검토한 읽기·메모리 처리 셀만 실행하며, 파일 저장 셀은 실행하지 않는다. 원본 노트북이 달라지면 재검토 없이 실행하지 않는다. 원본 개인 정보는 전처리 중 메모리에서만 사용하고 결과로 내보내지 않는다.

## 산출물

- `REPORT.md`: 결과 해석과 권고.
- `run_comparison.py`: 원본 재구성, 저장 모델 재현, 비교 실험, 결과 저장.
- `verify_results.py`: 저장된 OOF 확률에서 집계 지표와 분할을 독립적으로 재확인.
- `diagnose_compression.py`: 저장 GMM에서 한 변수의 수준만 바꾸었을 때 묶음의 출력도 바뀌는지 확인. 관측된 숫자 수준의 가능한 조합을 열거하는 구조 검사이며, 교차검증 성능과 구분한다.
- `results/comparison.json`: 전체 설정, 집계, fold별 결과.
- `results/protocol.json`: 버전, 설정, 원본·모델 해시와 변경 여부.
- `results/metrics.csv`: 방식별 전체 성능.
- `results/class_metrics.csv`: 등급별 예측 건수·비율·재현율·정밀도.
- `results/fold_metrics.csv`: fold별 성능.
- `results/compression_diagnostics.json`: 원문→숫자 매핑과 저장 GMM의 조합별 변환표, 변수별 출력 변화 여부.
- `results/psf*_oof.npz`: 식별 정보를 제외한 정답 코드, 그룹 번호, fold 번호, OOF 확률. 배열 행 순서는 해당 PSF의 전처리 후 응답 순서다.

저장된 결과는 `python -B research/gmm_comparison_20261118/verify_results.py`로 검증한다. 실행 코드와 근거 JSON의 SHA-256은 원시 바이트를 기준으로 하므로 상위 `.gitattributes`에서 해당 파일의 줄바꿈 변환을 제어한다. 기록된 JSON을 재포맷하면 보고서의 원본 해시도 달라진다.

## 해석 범위

이번 실험은 **현재 필터링된 설문의 새 원본 시나리오**에 대한 비교다. 응답자 단위 분할은 아니므로 새 응답자·새 기관에 대한 일반화나 실제 사고 예측을 검증하지 않는다. 여러 시나리오에 같은 사람이 답했을 수 있다. 표본에서 한 번도 관측하지 못한 변수 수준과 전체 가능한 조합의 성능도 검증하지 않는다.

GMM 방식의 비교는 기존 묶음과 추정 설정을 유지하되 fold별로 다시 학습한 결과다. 전체 자료로 만든 저장 GMM을 먼저 적용한 기존 노트북의 교차검증 수치와 직접 동일시할 수 없다. 하나의 분할과 seed를 사용한 비교이므로 작은 차이만으로 통계적 우월성을 주장하지 않는다. 결합 방식에서 특성 수와 중복 표현이 늘어나는 효과도 함께 포함된다.

PSF4 결과는 저장된 **교육 및 훈련 CatBoost**에 대한 것이다. 애플리케이션의 경과 개월 기반 계산 경로가 선택된 경우 그 계산식의 결과를 뜻하지 않는다. 새 모델을 운영에 교체하거나 원본을 수정하지 않는다.
