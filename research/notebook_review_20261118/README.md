# CatBoost 학습 노트북 및 저장 모델 검토

검토일: 2026-11-18. 대상: `Railway_hep/CatBoost_Result`의 세 노트북, 원본 설문·수준 매핑표, 기존 CatBoost/GMM 모델, 현재 학습·추론 경로.

**기존 모델의 학습 데이터 변환과 모델 생성은 재현된다. 그러나 노트북 전체를 그대로 최종 학습·검증 파이프라인이나 성능 보증 자료로 사용하기에는 평가 방식과 실행 상태 관리에 중요한 문제가 있다.**

`.ipynb`는 코드와 실행 결과를 담은 노트북이고, 실제 학습된 모델 파일은 `models/*.cbm` 및 `models/gmm/*.joblib`이다. 이번 검토에서는 노트북·원본 데이터·배포 모델을 수정하지 않았다. 재학습 모델은 메모리에만 만들었고 파일로 저장하지 않았다.

이 문서의 **셀 번호는 JSON 배열에서 0부터 세는 위치**이다. Jupyter의 `In [번호]` 실행 번호와 다르다. 원본 해시는 `results.json`에 기록했다.

## 2. 직접 실행한 검증

1. 원본 TXT를 읽고 원본 전처리 노트북의 검토된 읽기·변환 셀만 실행해 응답과 품질 구분을 재구성했다. 파일 저장 셀은 실행하지 않았다.
2. 매핑 XLSX와 저장된 GMM으로 기존 모델 입력을 복원했다.
3. 8개 기존 모델을 각각 메모리에서 새로 학습했다. **총 23,462개 학습 행에서 저장 모델과 새 모델의 예측 확률 차이가 모두 0.0이었다.**
4. 노트북 2장의 함수로 PSF별 5-fold 평가를 다시 실행했다. 총 40개의 fold 모델이며, 최종 재학습 비교 8개를 합하면 48개 모델을 메모리에서 학습했다.
5. 후반의 `scenario_label_kfold_split`을 실제 원변수 시나리오에 적용해 중복 및 fold 크기를 검사했다. 이 후반 튜닝 전체를 다시 수행한 것은 아니다.
6. 저장된 출력·함수 재정의·누락 경로·중단된 실행을 검토했다.

환경의 **기존 6개 GMM 특성 모델**을 재현한 검사이며, 현재 API가 사용하는 원변수 14개 모델과 구분해야 한다. 최신 PSF6의 별도 학습 경로는 `training/train_environment_raw14.py`이다.

재학습 확률 일치는 **학습 데이터와 모델 생성의 재현성**을 보여준다. 이를 미관측 데이터 정확도로 해석하면 안 된다. 보호 대상 원본 파일 해시도 실행 전후 동일했다.

### 수면시간에 대한 결론

원본 전처리의 셀 110은 매핑 XLSX를 읽고, 셀 119는 응답 문구를 `level`로 변환한다. 표는 8시간 이상→0, 6~8시간→1, 6시간 이내→2이다. 이 경로로 재구성한 작업부하 2,971건으로 새로 학습한 모델이 저장 모델과 확률까지 일치했다.

## 4. 중요: 후반 분할은 시나리오 GroupKFold가 아님

근거: `analysis_v1.5.ipynb` 셀 64·71의 `scenario_label_kfold_split`, 호출 셀 65·73.

이 함수는 시나리오 전체를 한 fold에 배정하지 않는다. **각 시나리오의 같은 정답을 가진 응답들을 여러 fold에 나누어 배정한다.** 따라서 같은 상황이 학습과 평가에 함께 존재한다.

예를 들어 같은 시나리오에 보통 7건·나쁨 3건이 있으면 다섯 평가 fold 크기는 3·3·2·1·1건이다. 모든 fold에서 동일 시나리오가 학습에도 남는다. 이는 이미 관측한 시나리오의 다른 응답을 예측하는 평가로 정의할 수 있지만, 처음 보는 시나리오에 대한 평가로 부를 수 없다.

원변수 실제 데이터에 적용한 결과:

| PSF | 다섯 fold의 평가 건수 |
| --- | --- |
| 장비 및 기기 | 1,905 / 700 / 207 / 44 / 11 |
| 교육 및 훈련 | **2,116 / 532 / 78 / 17 / 4** |
| 복잡성 | 1,819 / 838 / 325 / 96 / 27 |

각 시나리오·정답 소그룹의 첫 응답을 항상 fold 1부터 배정하기 때문에 이런 불균형이 생긴다. 단일 응답은 전부 첫 fold로 간다. 원변수 환경에 적용하면 비어 있지 않은 fold도 3개뿐이다. 원래 노트북 후반의 주요 대상은 PSF2·4·8이므로, 환경 결과는 이 분할 함수를 다른 PSF에 일반화했을 때의 진단이다.

후반 코드가 `fold_df['raw_accuracy'].mean()`을 사용하는 점도 문제다. 교육·훈련에서는 2,116건짜리 fold와 4건짜리 fold가 같은 가중치를 갖는다. 응답 기준 정확도는 모든 OOF 정답·예측을 모아 계산하거나 fold 표본 수로 가중해야 한다.

권고: ‘미관측 시나리오’ 검증은 원변수 조합을 그룹으로 한 GroupKFold를 유지한다. ‘새 응답자’가 목표라면 사람 기준 분할을 별도 제공한다. 앞부분의 올바른 시나리오 GroupKFold에도 같은 사람이 양쪽에 있는 것은 현재 평가 목적상 자동으로 오류는 아니지만, 새 응답자 검증으로 해석할 수 없다.

## 5. 중요: 상대 지표 90%대를 일반 정확도로 읽으면 안 됨

근거: 분석 셀 20·23.

노트북의 지표는 다음과 같다.

`상대 지표 = 맞힌 응답 수 / Σ(각 평가 시나리오의 가장 많은 응답 수)`

이는 정해진 시나리오 표현 아래 전문가 다수 응답 기준에 얼마나 가까운지를 나타내는 보조 지표로 사용할 수 있다. **수식 자체를 일반 정확도로 바꾸라는 뜻은 아니다.**

저장된 환경 결과를 예로 들면:

- 실제 맞힌 응답 비율: 2,145 / 2,950 = **72.71%**.
- 시나리오별 다수 응답 합: 2,235건.
- 상대 지표: 2,145 / 2,235 = **95.97%**.
- 실제 나쁨 응답도 2,145건이므로, 입력을 보지 않고 전부 나쁨이라고 답하는 기준도 동일한 72.71%와 95.97%를 얻을 수 있다.

또한 GMM이 서로 다른 원래 상황을 같은 입력으로 합치면 이 분모도 달라진다.

| PSF | 원래 시나리오 수 | 모델 입력 시나리오 수 | 원래 시나리오의 관측 다수 응답 비율 | 모델 입력 시나리오의 관측 다수 응답 비율 |
| --- | ---: | ---: | ---: | ---: |
| 장비 및 기기 | 1,255 | 162 | 74.71% | 57.73% |
| 교육 및 훈련 | 1,562 | 243 | 78.59% | 58.06% |
| 환경 | 2,762 | 474 | 97.83% | 75.76% |
| 복잡성 | 928 | 108 | 64.44% | 49.15% |

예를 들어 교육·훈련은 같은 데이터라도 표현을 묶으면서 이 비율이 78.59%에서 58.06%로 낮아진다. 따라서 상대 지표가 높다는 이유만으로 GMM이 원래 문항 정보를 충분히 보존했다고 판단할 수 없다.

여기서 다수 응답 비율은 **유한한 관측 데이터에서 계산한 경험적 값**이다. 단일 응답 시나리오는 자동으로 100% 기여하므로, 원변수 환경의 97.83%를 미관측 데이터에서도 달성 가능한 이론적 정확도라고 해석하면 안 된다.

다른 fold 모델이 같은 시나리오에 서로 다른 등급을 내는 후반 평가에서는 ‘시나리오당 하나의 고정 예측’이라는 분모 해석도 깨질 수 있다. 함수에 정답=[보통,보통,나쁨,나쁨], 예측=정답, 동일 시나리오 번호를 전달하면 4/2=200%가 나온다. 이는 현재 실험에서 실제로 200%가 관측됐다는 뜻이 아니라, 지표의 상한이 유지되는 조건을 보여주는 재현 예시다.

권고: 일반 정확도·균형 정확도·등급별 재현율·혼동행렬·최빈 등급 기준과 함께 표시하고, 상대 지표는 시나리오 표현·분자·분모를 명시한 별도 열로 유지한다.

## 6. 중요: 실행 상태와 실험 결과가 섞여 있음

근거: 분석 셀 21·38·48·53·60·65·73에서 같은 함수 `run_catboost_by_psf`를 7번 정의한다. `quality_psf_tables`, `model`, `psf_model_results` 등도 여러 실험에 재사용된다.

실제 저장 출력에도 서로 다른 조건이 섞여 있다.

- 셀 22~23의 복잡성: 입력 5개, 시나리오 108개, 일반 정확도 46.45%.
- 셀 26의 같은 결과 변수 참조: 학습·평가 시나리오 합이 928개.
- 셀 27~28의 분류 보고서·혼동행렬: 정답 1,380/3,105 = 44.44%.

뒤 결과는 원변수 7개 실험과 맞는 규모이며, 앞의 5개 복합 특성 결과와 한 세트로 볼 수 없다. 코드가 틀렸다기보다 **현재 저장된 노트북이 한 번의 순차 실행 결과를 보존하지 않고 있다.**

부분 재실행은 더 위험하다. 셀 73의 최신 함수는 `drop_base_cols` 기본값이 빈 목록인데, 앞쪽 셀 22는 그 인자를 넘기지 않는다. 실제 함수에 예시 컬럼을 넣으면 `empid`, `survey_id`, `quality_95`가 특성 목록에 남았다. 최신 정의가 살아 있는 상태에서 앞쪽 실행 셀을 다시 돌리면 식별 정보가 특성에 들어가거나 시나리오 구분이 달라질 수 있다. **현재 저장 모델에 그런 컬럼이 들어갔다는 뜻은 아니며, 저장 모델의 실제 특성은 정상임을 확인했다.**

셀 50·55에는 KeyboardInterrupt가 남아 있고, 셀 56은 실행 번호가 없는데도 이전 결과 표가 남아 있다. 셀 62·67·75는 서로 다른 분할 실험인데 같은 `psf_parallel_tuning_summary_latest.csv`·XLSX 경로를 덮어쓴다. 해당 결과 CSV 자체는 현재 프로젝트에 없어 후반 최적 설정 전체를 독립 검증할 수 없다.

권고: 실험별 함수명·결과 객체·저장 경로를 분리하고, 입력 표현·분할 방식·품질 기준·시드·버전·fold 목록을 결과에 함께 저장한다. 확정 표는 새 커널에서 한 번 실행해 생성한 산출물로 만든다.

## 7. GMM의 평가와 배포를 구분해야 함

`env_preprocess_v1.ipynb` 셀 4는 전달된 전체 데이터에 `gmm.fit_predict(X)`를 수행한다. 분석 노트북은 이미 만들어진 복합 CSV를 읽은 뒤 CatBoost만 교차검증한다.

최종 배포 모델을 만들기 위해 전체 학습 자료로 GMM과 CatBoost를 적합하는 것은 자연스럽다. 그러나 평가 단계까지 같은 전체 적합 GMM을 쓰면 평가 자료의 특성 분포가 전처리에 먼저 반영된다. **정답을 GMM에 직접 넣는 누수는 아니지만, 미관측 자료 검증에서는 fold 내부 적합이 필요하다.** 이번 40-fold 재실행 역시 저장 GMM을 사용했으므로 이 문제를 해결한 성능 추정치는 아니다.

현재 저장 GMM에서 일부 문항 변화가 완전히 사라지는 현상도 앞선 전수 검사로 확인됐다.

- PSF2: 컴퓨터 지원 시스템의 적절성.
- PSF8: 의사결정 대안의 수, 추론해야 하는 정보의 양.
- 보조 PSF4 모델: 직무능력 평가 빈도, 장비 사용 지식의 숙련도.

이 사실만으로 문항이 현실에서 중요하지 않다고 결론 내리면 안 된다. 군집 변환이 해당 정보를 버리는지와 그 정보가 실제 응답 예측에 유용한지를 분리해 비교해야 한다. 자세한 3×3 변환표는 [앞선 코드 검토](../code_review_20261118/README.md)에 있다.

## 8. 기타 결과 해석·데이터 처리 확인

### ‘응답 2명 이상’과 ‘응답 2건 이상’의 차이

분석 셀 10~13은 `groupby(...).size()`로 응답 행을 센다. 동일인이 같은 시나리오에 반복 응답한 것도 여러 건이다.

원변수 기준으로 장비는 응답 2건 이상 시나리오 846개지만 서로 다른 사람 2명 이상은 840개였다. 교육·훈련은 795개 대 786개, 의사소통은 663개 대 660개였다. 따라서 표 제목의 ‘2명 이상’은 ‘2건 이상’으로 바꾸거나 고유 응답자 수를 사용해야 한다. 실제로 이 차이를 그대로 데이터 삭제 조건으로 적용하지는 않았다.

### 성실도 95%는 정확도나 응답 일치율 95%가 아님

전처리 셀 50~56은 한 설문 안의 두 PSF 모두에서 동일 등급 응답 비율이 95% 이상인 경우를 표시하고, 같은 사람·연도에 30건 이상인 성실 설문이 하나라도 있으면 해당 연도 예외를 적용한다. 실제로 14개 설문이 예외로 복원되어 성실 406→420개, 불성실 66→52개가 됐다.

규칙은 재현되지만 자동으로 객관적 불성실 여부가 입증되는 것은 아니다. 보고서에는 ‘동일 응답 반복률과 연도 예외에 따른 분석 포함 기준’으로 설명해야 한다. 이 기준에 따라 데이터 분포가 바뀐다는 점도 남겨야 한다.

### X1·X2와 분포 기반 실험은 별도 평가임

X1은 여러 PSF·직업·나이 등을 사용하고 사람 기준으로 나눈다. X2는 작업부하 5개만 쓰지만 숫자 입력으로 학습하고 사람 기준으로 나눈다. 앞부분의 범주형 입력·시나리오 분할 모델과 실험 조건이 다르다.

X2 저장 결과의 일반 정확도는 55.57%인데 ±1단계 허용 정확도는 95.63%이다. 3등급 문제에서 항상 가운데 등급만 답하면 ±1단계 지표는 100%가 된다. 따라서 이를 일반 정확도 개선으로 제시하면 안 된다. Top-2 정확도 88.70%도 항상 다수 두 등급만 제시하는 기준 88.55%와 거의 같다.

4장의 `distribution_overlap_by_scenario`는 `predict_proba`가 아닌 **최종 예측 등급 빈도**를 비교한다. 이는 주변 분포 중첩이라는 계산으로는 성립하지만, 모델이 전문가 판단 확률을 얼마나 잘 추정했는지를 직접 검증하지 않는다. 서로 전부 틀린 예측이라도 양쪽 등급 개수가 같으면 중첩도는 100%가 될 수 있다. 확률 분포를 평가하려면 시나리오별 예측 확률과 응답 비율을 비교하고 log loss/Brier score 등을 별도로 계산해야 한다.

## 9. 현재 운영 경로와 노트북의 차이

- 셀 25의 모델 저장은 고정된 2장 설정으로 전체 학습한다. 후반 튜닝 결과에서 최적 설정을 읽어 배포 모델로 저장하는 연결은 없다. 후반 최고 점수를 현재 배포 모델의 점수로 소개할 수 없다.
- 노트북의 환경 모델은 GMM 6특성 및 `환경_catboost.cbm`이다. 현재 API는 `환경_raw14_catboost.cbm`과 별도 14특성 학습 스크립트를 사용한다.
- 기본 API의 PSF4는 경과 개월 수 공식이다. PSF4의 GMM·CatBoost 모델 평가는 보조 예측 경로에 해당한다.
- 현재 폴더에는 노트북이 처음 읽는 `data.csv`와 중간 `processed_data/psf_tables/number`, `string` CSV가 없다. 이번 검토는 원본 TXT에서 필요한 변환을 따로 재구성한 것이며 노트북 전체 실행에 성공했다는 의미가 아니다.
- 전처리 셀 217은 장비 저장 부분에서 `equip_gmm` 등 앞에서 일관되게 정의되지 않은 이름과 환경 관련 인자를 사용한다. 저장 오류는 `thermal_gmm` NameError로 남아 있어 소스와 실행 결과 상태도 일치하지 않는다. 현재 사용 중인 GMM 번들은 별도의 `env_preprocess_v1.ipynb` 저장 경로로 검토해야 한다.
- 경로가 작업 디렉터리에 의존하고 `max(...mtime)`으로 최신 CSV를 고르는 방식이므로, 데이터 버전이 명시되지 않으면 같은 코드로 다른 자료를 학습할 수 있다.

## 10. 권장 정리 순서

1. 확정 평가 목표를 ‘미관측 시나리오’와 ‘새 응답자’로 분리한다. 기본 연구 결과는 원변수 조합 GroupKFold로 고정한다.
2. GMM·결측 대체 등 적합이 필요한 전처리를 학습 fold 안으로 옮긴다. 현재 고정 GMM 결과와 성능을 구분한다.
3. 실제 정확도·균형 정확도·등급별 재현율·혼동행렬·최빈 등급 기준을 공통 표로 만들고 상대 지표는 보조 열로 둔다.
4. 노트북은 탐색과 그림에 사용하고, 확정 학습·평가·저장은 함수 또는 CLI로 분리한다. 같은 함수명을 재정의하는 셀과 중단된 출력은 확정 결과에서 제외한다.
5. 선택한 설정·원본/스키마 해시·패키지 버전·fold 목록·모델 파일명을 하나의 실험 기록으로 연결한다. 튜닝 최적값은 별도의 평가로 확인한 뒤 최종 학습에 전달한다.
6. PSF6 원변수 경로와 PSF4 기본 공식 경로를 기준으로 문서와 재학습 대상을 명확히 한다. 검증 없이 기존 모델 파일을 일괄 교체할 필요는 없다.
